## 操作

「論証の本筋」は通常の命題・反論、「準備・確認も」は留保調書・未獲得供述・確認課題を含む全体。グラフの点または命題一覧を選ぶと、本文・出典・前提・反論・確認事項を表示する。点のサイズは表示重要度であり、証拠力ではない。グラフは自然配置で、ドラッグ・拡縮・全体表示ができる。

検索はID・命題・本文に対応。本文の接続リンクから別ノートへ進める。選択IDと検索・表示範囲はURLに保存されるため、そのURLを共有できる。上部の「使い方・資料」からREADMEや資料索引も読める。

線だけを支持と判断しない。選択した命題に関係する線と、本文の接続欄で支持・反論・確認・準備・将来候補を区別する。準備・候補は現在の証拠支持に昇格させない。資料を読み終えても未確認・未レビュー状態は変わらない。

表示調整の追加依頼（2026-10-24）：通常は全体を明るく表示し、点へのホバー・キーボードフォーカス・クリック選択のときだけ関係外を暗くする。既定の本文や初期URLの指定だけでは暗くしない。背景クリック・Escape・「画面に収める」で強調を解除する。右上の全体／周辺切替は撤去し、以前の`graph=local`付きURLも全体表示として開く。本筋／準備・確認の切替と力・表示の設定は維持する。

配置計算の継続（2026-10-24追加）：初期表示・力設定の変更・ドラッグ解放後は最低3秒間計算を続け、その後冷却して落ち着かせる。放置時は最大8秒で止まり、手動停止・非表示タブ・ページ離脱ではすぐ止める。OS等で動きを減らしている場合も計算は同じ時間続け、毎フレームのアニメーションだけ省いて終了時に結果を表示する。一瞬の同期計算だけで済ませない。

## 同期される時点

### 力・表示設定の引継ぎ

2026-10-24の依頼により、端末の`.obsidian/graph.json`から保存済みの設定を`web/graph-settings.json`へ取り出した。取得元の保存時刻は2026-10-21 22:23:52（日本時間）。起動中のObsidianは確認できなかったため、ライブの画面から取得した設定とは説明しない。Extended Graphの別プリセットや個人のピンを混ぜない。

2026-10-24の追加依頼で、ユーザー提示画像の力の4項目を共有既定値へ反映した。中心力0.28・反発力36.5・リンクの力0.88・距離295で、その他の表示値は初回取得値を維持する。Obsidianの個人設定は変更しない。共有設定ハッシュも更新するため、以前のブラウザ内調整より新しい既定値を優先する。

| 項目 | 現在の共有既定値 | Pagesでの使い方 |
|---|---|---|
| 中心力 | 0.28 | D3のX/Y位置の力に0.1倍して設定 |
| 反発力 | 36.5 | D3の多体力に−60倍して設定 |
| リンクの力 | 0.88 | D3のリンクの強さへ設定 |
| リンク距離 | 295 | D3のリンクの目標距離へ設定 |
| 点のサイズ | 0.8 | 表示重要度別の半径へ乗算。T00が最大という意味を保持 |
| 線の太さ | 1 | 基準線幅へ乗算 |
| 文字のしきい値 | −2.5 | 表示倍率との組合せで文字の不透明度へ換算。選択・ホバー時は明瞭に表示 |
| 矢印 | 表示 | 関係の向きを表示 |
| 色グループ | T00・検察・弁護・共通 | 保存済みのRGB値を点・凡例へ反映 |

PagesのエンジンはD3で、Obsidianの非公開の力学ソルバーとは異なる。数値の意味を対応させたもので、座標・動き・しきい値の見え方が完全一致するとは限らない。保存倍率`scale`は取得記録に残し、初期画角はPC／スマホに収まるよう自動換算する。パン・ピン・絶対座標は共有しない。

本筋／詳細の表示範囲は正本の分類から作り、Obsidianの任意の検索式を実行するわけではない。孤立点表示は保存値を反映する。タグ・添付・未解決リンクの保存値も記録するが、現在の公開グラフは正本の命題だけを点にするため、これらの種類の点は追加しない。

画面右上の「力・表示」では初期値と調整を確認できる。調整はそのブラウザだけに保存され、Obsidianや他の参加者の設定を書き換えない。「共有設定に戻す」で今回の共有値へ戻る。共有設定のハッシュが更新された場合は、新しい共有値が初期値になる。

今後Obsidianで調整した設定を共有し直す場合だけ、作業ブランチ上で次を実行し、差分を確認してPRへ含める。通常のノート更新やCIではこの取り込みを自動実行しない。

```powershell
python 作成用/export_graph_settings.py
python 作成用/verify_repository.py
python 作成用/build_pages.py
```

元のObsidian設定は読取のみ。取り出すのは対象項目だけで、workspaceや個人のピンは公開しない。

### 正本・本文の同期

1. 手元でmainをpullし、作業ブランチを作る。
2. Obsidianの正本を編集し、通常更新・検査・Pagesビルドを実行する。
3. 作業ブランチをpushし、PRで内容とCIを確認する。この時点では公開画面は変わらない。
4. mainへマージすると`GitHub Pages`ワークフローが正本から再ビルドし、成功した版を公開する。
5. 他の参加者はmainをpullし、必要に応じて起動中の対象保管庫をCLIでreloadする。

ローカルで保存しただけの変更、未コミット、未push、未マージの変更は公開画面に届かない。Pagesは編集操作を提供しないため、逆向きの自動書換えも行わない。常駐する監視・自動pushプロセスは置かない。ビルド失敗時はActionsのログを直し、公開済みの版を保つ。

## 実装と確認

表示ソースは`web/`。デザイン方針は[web/DESIGN.md](../web/DESIGN.md)。`作成用/build_pages.py`が正本全件とdocsを読み、`_site/`へHTML・CSS・JS・データ・本文で参照するファイルだけを出力する。ノート数は固定せず、新しい正本も次の公開ビルドに含む。`_site/`をGitへ入れず、HTMLを手で編集して正本との相違を作らない。

```powershell
python -m pip install -r requirements.txt
python 作成用/reasoning_graph.py
python 作成用/verify_repository.py
python 作成用/build_pages.py
```

`_site/index.html`はローカルでも開ける。原本ファイルのコピーは元資料を変更せずに作る。画像・PDFのページリンクも引き継ぐ。Markdown中のHTMLはテキストとして扱い、リンク・生成タグを制限する。Pagesに資格情報・個人のObsidian設定・Git管理情報を含めない。

公開ワークフローはmainへのpushと手動実行で配信し、PRでは検査・ビルドのみ。ビルドは読取権限、配信ジョブだけ`pages: write`と`id-token: write`を使う。リポジトリのPages設定はGitHub Actionsを選ぶ。

### 公開されない・古い場合

GitHubのActionsで最新mainの`GitHub Pages`が成功しているか確認する。失敗ならログの欠落資料・未更新表示・依存関係を修正する。成功後も古ければブラウザを再読込し、本文末尾の公開データIDを確認する。資料・命題の変更は正本に戻してPRで修正し、公開側の生成ファイルだけ直さない。
