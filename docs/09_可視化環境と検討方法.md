## 線を追わずに接続を読む

ルートの「つながりを開く.cmd」でローカルのHTMLをブラウザで開きます。外部通信や追加インストールは不要です。最初は犯人性T01を表示し、左の前提を選ぶと証拠へ、右の使われる先を選ぶと立証目標へ進めます。反論・確認課題は下段、供述準備と将来の候補は別枠に表示します。全体図の代替表示であり、新しい分割Canvasを作るものではありません。

閲覧画面から正本を書き換える機能はありません。「Obsidianで編集する」で戻り、編集後は既存の更新コマンドを実行してブラウザを再読込します。外部アプリリンクの起動は保管庫登録とOSの関連付けに依存します。コードとデザインの理由は [接続画面の設計](../作成用/接続画面_DESIGN.md) にあります。

## 選定結果

このフォルダ全体をObsidianの保管庫として使い、ノートはMarkdown、図は標準Canvasで管理します。追加のコミュニティプラグイン、AIプラグイン、同期契約は今回導入していません。Obsidian本体は無料で利用でき、Canvasも標準機能です。[公式料金](https://obsidian.md/pricing)、[公式Canvas](https://obsidian.md/canvas)

| 候補 | 今回との相性・判断 |
|---|---|
| Obsidian＋標準Canvas | 既存Markdownを活かし、ファイルのカードを線で結べる。本件の編集の正本と図を近づけやすいため採用 |
| draw.io | 既存資産があり、ラベル・リンク付きの図に向く。今回の各事実・反論の継続編集では、Markdownのノートとの対応を別に管理する必要があるため補助として保持 |
| Logseq Whiteboards | ノートとホワイトボードを結ぶ選択肢。今回は既存フォルダをそのまま扱う構成と、導入する道具を一つに絞る判断を優先 |

比較は本件の作業に対する判断です。[draw.ioのリンク・タグ機能](https://www.drawio.com/docs/manual/links-tooltips-tags/)、[Logseqの公式Whiteboard資料](https://github.com/logseq/docs/blob/master/pages/Whiteboard.md) を確認しました。

Obsidianの通常グラフはノート間のリンクを確認するのに便利ですが、線だけで「支持」「反論」「未確認の前提」までは十分に伝わりません。このため主な作業画面には、役割を明示したCanvasを採用しました。Canvasはノートや画像等のファイルをカードとして配置し、線にラベルを付けられます。[公式Canvasヘルプ](https://obsidian.md/help/plugins/canvas)

## 初めて開く手順

Obsidianはインストール済みです。初回は次の操作で保管庫を開きます。

1. Obsidianを起動する。
2. 「フォルダを保管庫として開く（Open folder as vault）」を選ぶ。
3. このプロジェクトのルートフォルダ `模擬裁判_検察官準備_20261020` を選ぶ。`検討` や `docs` だけを選ばない。
4. 左側の一覧から `検討/00_はじめに.md` を開く。
5. 「00 全体ピラミッド」を開く。全体表示は `Shift+1`、選択カードへのズームは `Shift+2`、移動はSpaceを押しながらドラッグ。

保管庫はMarkdownを置くローカルフォルダとして扱われます。[公式保管庫案内](https://obsidian.md/help/Files+and+folders/Manage+vaults)

初回にフォルダを開いた後は、ルートの「Obsidianで検討を開く.cmd」でも入口を開けます。保管庫の登録と、Obsidianでのノート・Canvasの表示を確認しています。

## ファイルの役割

| 場所 | 役割・編集 |
|---|---|
| `検討/ノート/*.md` | 命題・出典・前提・反論・レビューの正本。人間もAIもここを編集 |
| `検討/Canvas/*.canvas` | 図の配置と表示。人の位置・手描きカードも保持 |
| `検討/レビュー一覧.md` | 自動生成の一覧。直接の編集は次回更新で置換される |
| `検討/接続を読む.md` | 自動生成の接続ガイド。前提・使われる先・反論・確認事項を双方向にたどる。編集はリンク先の正本ノートで行う |
| `検討/つながりをたどる.html` | 自動生成のブラウザ閲覧画面。ノートの保存時点の写し。直接編集しない |
| `検討/グラフ表示/` | 標準グラフ用の命題ノート。直接リンクと接続表を自動生成。編集用正本へのリンクを持つ。関係名の中間ノートは廃止 |
| `検討/確認用プレビュー/*.svg` | 自動生成の静的プレビュー。編集はノート・Canvasで行う |
| `検討/テンプレート/新しい検討ノート.md` | 新しいカードのひな形 |
| `.obsidian/` | この保管庫用の最小限の標準機能設定 |
| `作成用/reasoning_graph.py` | 関係検査、図の更新、レビュー表の生成 |

図のデータ形式は公開仕様のJSON Canvasです。[仕様](https://jsoncanvas.org/spec/1.0/)。単なるテキストカードはバックリンクに現れないとの制約があるため、分析内容はファイルのカードにしました。[公式Canvasヘルプ](https://obsidian.md/help/plugins/canvas)

## レビューと関係のプロパティ

Obsidianのプロパティはノートの上部で編集できます。Markdownの先頭にあるYAMLにも保存されます。[公式Properties案内](https://obsidian.md/help/Editing+and+formatting/Properties)

| プロパティ | 内容 |
|---|---|
| `id` / `title` / `kind` | ID、見出し、証拠・間接事実・推認・要証事実・反論・確認課題 |
| `side` | 共通・検察・弁護。確信度ではない |
| `status` | 採用済み・採否留保・法廷未確認・推論案等。資料や命題の状態 |
| `review` | 人の判断。未レビュー・検討中・採用・保留・不採用 |
| `reviewer` / `reviewed_on` | 人の採用を記録する際の確認者・日付 |
| `source_group` | 同じ物や記録に由来する情報をまとめる。独立性の自動判定ではない |
| `inputs` | この命題を支える前提ノートへのリンク |
| `challenges` | この反論が疑問を向けるノートへのリンク |
| `checks` | この質問・確認課題の対象ノートへのリンク |
| `answered_objections` | 本文に応答を書き、人が確認した反論へのリンク |
| `court_record` | 法廷確認済みとする根拠の記録ファイル。プロジェクトルートからの相対パス |
| `preparation` | 供述獲得の準備に参照する資料。証明の前提とは区別 |
| `potential_supports` | 供述獲得後に支え得る対象。現在の証拠支持や原稿化チェックには数えない |

`status`を採否留保から変える場合は、実際の採否・供述根拠を確認し、元の証拠表も更新します。人の判断が「採用」であっても証拠の採否を変えません。単に `court_record` があるだけで内容が十分かは、人が確認します。

## 公平に深めるための運用

線を追いにくい場合は [接続を読む](../検討/接続を読む.md) を入口にします。各接続は正本のプロパティから生成され、準備関係・供述獲得後の候補を現在の支持と分けて表示します。この案内はCanvasを分割せず、既存の配置を変えません。

1. まず証拠の記載と利用範囲を双方共通で確認する。
2. 検察側の推認について、前提と橋渡しの条件を書く。
3. 弁護側から、その条件への最も強い反論・別の説明を書く。
4. 反論にも、何が証拠に基づき、何が仮説にとどまるかを書く。
5. 反論への検察側の応答と、その応答に残る限界を確認する。
6. 人間が判断理由を記録し、必要な確認作業を選ぶ。
7. 選んだ主張だけを段落案へ進め、段落に根拠IDを付ける。

公平さは、双方のノート数を同じにしたり証拠価値を同じとみなしたりすることではありません。検察官の証明責任を保ったまま、双方の最も強い説明と限界を検討します。弁護側に真犯人の特定を要求しません。

## 更新・保護・限界

ルートの「検討を更新.cmd」で図・一覧を更新します。PythonとPyYAMLは現在の環境で動作確認済みです。別のPCへ移す場合、Obsidianでノートを読む・編集するだけならPythonは不要ですが、自動更新にはこれらの実行環境が必要です。

更新処理はMarkdownノートを上書きしません。既存Canvasの位置・大きさ・手描きカードを保持し、変更があるCanvasは `作成用/構造化確認/Canvas前回/` に一世代保存します。バックアップは一世代だけなので、作業の節目にはフォルダを別の場所へコピーしてください。クラウド同期や複数人の同時編集・競合解決は今回設定していません。

ノートの入力関係に循環、参照切れ、ID重複等があれば更新を止めます。反論同士の往復は、正の支持の循環とは区別します。機械的な整合性検査は、推論の妥当性や合理的な疑いの有無を判定しません。

現在は全ノートを「00 全体ピラミッド」に自動配置します。頂点T00は「被告人は有罪である」であり、検察側の立証目標を示します。以前の分割図4件とプレビュー・バックアップはユーザー指示により削除しました。新しいノートも更新時に全体図へ追加されます。手描きの支持線はノートの `inputs` に反映しない限り原稿化チェックの対象になりません。
