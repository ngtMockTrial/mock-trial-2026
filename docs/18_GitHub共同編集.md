# GitHubでの共同編集

2026-10-22。運用の正典は[AGENTS.md](../AGENTS.md)。初参加者は本書→[AI・スキル導入](19_新しいAIとObsidianスキルの導入.md)→[検討の入口](../検討/00_はじめに.md)の順に読む。

## アップロード前に決めること

当面は**非公開リポジトリ**で始める。教材・配布写真・過去のZIP・生成PDFを含むため、公開配布と再利用の許諾は未確認。非公開でも、参加者への共有と利用するAIサービスへの投入が許される範囲を管理者が確認する。プロジェクト全体に一律のオープンソースライセンスを付けない。第三者プラグインの実行ファイルはGit対象外にして各自で導入する。

GitHubの所有者、リポジトリ名、参加者と権限は未指定。今回の作業ではリモート作成・push・参加者招待を行わない。原資料は移動・削除せず、現在のパスで共有する前提。共有できない原資料がある場合は、そのままpushせず共有方法とリンク検査を別途調整する。

管理者は初回push前に`git status --short --untracked-files=all`と`git diff --cached --stat`を確認する。元資料15件だけでなく履歴ZIP・スクリーンショット・PDFにも共有対象の情報が含まれる。`.gitignore`は内容の安全や権利を保証しない。

初回は空の非公開リポジトリ（README等を自動生成しない）をGitHubに作る。ローカルの内容を確認して`git add .`、`git diff --cached`、`git commit`を行い、GitHubが表示する実際のリモートURLを`git remote add origin`へ渡して`git push -u origin main`する。URLや所有者をAIに推測させない。認証情報をMarkdown・リモートURL・プロンプトに埋め込まない。

## 初参加のセットアップ

Git、Python 3.12以上、Obsidianを用意し、GitHubからcloneする。**clone先のフォルダ名は`模擬裁判_検察官準備_20261020`を使う**。生成済みObsidian URIが保管庫名を含むためで、親ディレクトリは自由。リポジトリ名自体は英語でもよい。別名でcloneした場合は生成物のURIが変わるため、共有前に管理者と命名を揃える。

以降はリポジトリのルートで実行する。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe 作成用/setup_collaborator.py
.venv/Scripts/python.exe 作成用/verify_repository.py
```

macOS/Linuxでは実行パスを`.venv/bin/python`に替える。以降の`python`は、この仮想環境のPythonを使う。Obsidianの画面がなくても検査できる。依存関係は日常のノート更新・検査に必要なPyYAMLのみ。以前のPDF・図解エクスポーターの再現環境を含むものではない。

Obsidianではルートを保管庫として開く。`setup_collaborator.py`は共有初期値から**存在しないJSONだけ**をコピーする。既存のグラフ・ブックマーク・ピン・表示設定は変更しない。Extended Graphは各自で導入する（[導入手順](19_新しいAIとObsidianスキルの導入.md)）。初期値は2026-10-22時点の共有用スナップショットで、自動同期の対象ではない。

## Gitへ入れるもの・各自に残すもの

| 共有する | 各端末だけに残す |
|---|---|
| 原資料、docs、正本ノート、Bases、全体Canvas一枚、生成コード | `.venv`、キャッシュ、資格情報、`.trash` |
| グラフ表示用ノート、生成台帳、閲覧HTML、レビュー一覧、プレビュー | `.obsidian`のJSON・プラグイン本体・ピン・workspace |
| 既存のoutput・図解・履歴資料（初回共有前に確認） | 個人のAIスキル・ローカル設定 |
| `作成用/obsidian初期設定/`とCSSスニペット | Canvasの一世代ローカルバックアップ |

生成台帳と派生ノートは同じ変更で共有する。台帳だけを消して強制再生成しない。Canvasには人の配置・手描きが含まれるため、単なる再生成可能なファイルと扱わない。初期設定を更新する場合だけ、個人のピン等を取り除いた共有用コピーをPRで変更する。

## 一つの変更の流れ

1. `git status`で未保存の作業がないか確認し、mainで`git pull --ff-only`する。作業途中の編集をresetで消さない。
2. 作業ごとに`git switch -c discussion/短い識別名`で枝を作る。IssueまたはPRに「担当者、対象ID・ファイル、問う命題、完了条件」を先に書く。同じノートの同時編集を避ける。複数のAIに作業させるときも人間が担当を決め、別cloneかworktreeを使う。
3. 原資料と反論を確認して正本を編集する。意味の変化はinputs・challenges・checks等と本文を揃え、変更記録へ日付・担当者・理由を書く。人のコメントを残し、AI案と人の判断を区別する。
4. `python 作成用/reasoning_graph.py`で派生を更新する。この処理内で`obsidian_graph.py`も呼ばれる。通常更新で`--reflow`や初期設定スクリプトは使わない。
5. `python 作成用/verify_repository.py`と`python 作成用/reasoning_graph.py --gate T00`を実行する。ゲートの終了コード2は保留で、CIの失敗とは分ける。
6. `git diff`で意図した正本変更と派生への反映を確認し、必要なファイルだけcommit・pushしてPRを作る。PR書式に出典・反論・未確認点と検査結果を記録する。
7. 別の参加者が原資料・橋渡し・最も強い反論を確認してからマージする。CI成功やPR承認は、ノートの人のreview・裁判所の証拠採用ではない。reviewを変えるなら対象命題について明示的な判断を別途記録する。

管理者はmainへの直接pushを制限し、`repository-check / verify`と人によるPR確認をマージ条件に設定する。これはGitHub側の設定であり、ファイルを置いただけでは有効にならない。利用プラン等で強制設定が使えない場合もPR確認を運用する。

## 衝突したとき

- **正本・レビュー**：双方の差分と原資料を読み、判断が食い違う場合は双方の案を残して人へ戻す。片方を自動採用したり、reviewを都合よく「採用」にしたりしない。
- **ノートID**：追加前に全IDを検索し、未使用IDをIssueで確保する。同じIDを二人が使った場合、マージ前に片方のID・本文リンク・関係属性をまとめて修正する。
- **生成ノート・台帳・HTML**：自分の未保存変更を保全してから、共通祖先などの整合した生成ノートと台帳の組を復元し、マージ済み正本から生成し直す。派生への手書きがあると更新は停止するので、正本へ移すかを人が確認する。衝突マーカーを含むまま生成しない。
- **Canvas**：人のカード・線・位置を比較して手動で統合した後、通常更新する。`--reflow`や片側ファイルの丸ごと採用で衝突を隠さない。
- **原資料**：ハッシュが違ったら停止し、別版なのか破損なのかを確認する。検査を通すためだけに既存ハッシュを書き換えない。追加資料は別ファイル・出典ID・確認日で登録する。

同じcloneをGitと別の同期サービスで同時同期させる運用は避ける。GitHubにpushしていない作業は他の人には届かない。同期前後にObsidianの編集中ノートを保存し、必要に応じて対象保管庫をCLIでreloadする。

## 自動確認の範囲と記録

`verify_repository.py`は読取専用で、原資料の全15件とハッシュ台帳の一致、主要Markdownのローカルリンク、正本ID・支持循環・参照・人の採用属性、標準グラフ・接続表示・Canvasの同期、回帰テストを確認する。リンク先のページ・節の内容や法的推論の正しさは自動判定しない。レビュー一覧・静的SVGの見た目は更新後に人が確認する。

GitHub Actionsはpush/PRで同じ検査を実行する。原稿化の保留をCI失敗にせず、T00の保留件数をログへ出す。クラウドからObsidianを操作したり、実演中の外部支援を行ったりしない。

2026-10-22の実行結果：

- ローカル検査：正本43件・原資料15件・主要Markdown69件が整合。既存22件＋共同編集保護3件＝25テスト成功。T00は37件の保留理由を保持。証拠採否・人のレビューを変更していない。
- Git対象461ファイル（約65.6MiB）だけを別の一時フォルダへコピーし、独立したPython仮想環境へ依存関係を導入。初期設定を2回実行（8件作成→0件上書き）、通常更新と25テスト・全検査が成功した。新規端末でのObsidian実画面は未確認。
- 原資料15件・正本43件・Canvas一枚・既存Obsidian設定等の計77ファイルは更新前後の内容ハッシュが一致。今回の導入検査は表示上の色・サイズの実画面確認を代替しない。
- GitHub上でのActions・ブランチ保護：リモート作成後に管理者が確認する。
