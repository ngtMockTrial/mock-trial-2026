# 新しいAIの参加とObsidianスキルの導入

2026-10-22。対象はこの保管庫を編集する参加者とAI。Obsidianスキルはファイル形式・アプリ操作の知識を補うもの。事件の根拠や採否、法的な判断は[AGENTS.md](../AGENTS.md)と原資料に従う。

## 最初にAIへ渡す依頼

以下を新しいチャットへ渡す。担当と完了条件は実際の作業に置き換える。

```text
このリポジトリのAGENTS.md、README.md、docs/README.mdを読んでください。
docs/17_検討の仕組みの評価と深め方.mdとdocs/18_GitHub共同編集.mdも確認してください。
担当：対象ノートID・ファイルと、今回問う一つの命題をここに指定。
完了条件：号証・教材ページを確認し、推論の橋渡し、双方の強い説明、
前提を外した比較、残る疑問を正本へ追記して変更理由を残すこと。
人のreview・コメントと証拠採否は、明示された判断なしに変更しないでください。
原資料・留保調書・想定回答・実際の供述を混同しないでください。
通常更新とverify_repository.pyを実行し、原稿化ゲートの保留理由を報告してください。
原稿、リモートへのpush、他の人への連絡は今回の担当に含む場合だけ行ってください。
```

最初から全資料を全文投入する必要はない。資料台帳→証拠表→対象の正本→反論・確認→原資料の該当箇所とたどる。必要な図・写真は実画像を見る。過去のAI案を独立の根拠にしない。

## 何を導入するか

導入元は[kepano/obsidian-skills](https://github.com/kepano/obsidian-skills)。本書の案内は2026-10-22に上流READMEで確認した。各参加者のAI環境へ導入し、リポジトリの正本へコピーしない。

| スキル | このプロジェクトで使う場面 |
|---|---|
| `obsidian-markdown` | 正本のfrontmatter、wikilink、注記の編集 |
| `obsidian-cli` | 起動中の保管庫を読み、reload、プラグイン確認を行う |
| `obsidian-bases` | `検討/論証一覧.base`を変更する場合 |
| `json-canvas` | Canvas実装を変更する場合。通常は生成コードを使う |
| `defuddle`・`knap` | 上流に含まれる追加用途。今回の日常更新には必須ではない |

AIスキル、Obsidianアプリ、Extended Graphプラグイン、Pythonの依存関係は別々。スキルだけ入れてもアプリやプラグインは導入されない。スキルの説明とプロジェクト規約が食い違ったら、依頼内容とプロジェクト規約を優先する。

## 導入方法

Node.js/npmとGitが使える環境では、上流案内のHTTPS版を使える。

```sh
npx skills add https://github.com/kepano/obsidian-skills
```

インストーラーの案内で利用するAIと必要なスキルを選ぶ。既に同名スキルがある場合は、内容と導入元を確認してから更新する。上書き目的の一括削除はしない。実行後、AI環境を再読み込みまたは新しいチャットを開き、利用可能なスキル一覧と`SKILL.md`の実在を確認する。上流の更新は自動適用せず、導入日と使用したコミットまたはバージョンをPR等に残す。

手動の場合は上流を**保管庫の外へ**cloneし、各スキルのフォルダ全体（`SKILL.md`と`references/`等）をAIのスキル保存先へコピーする。`SKILL.md`だけをコピーしない。上流READMEではCodexの保存先の例を`~/.codex/skills`としている。実際の保存先がカスタマイズされていれば、その環境の設定を使う。

Claude Codeのプラグイン方式は上流READMEにある次のコマンドを使う。

```text
/plugin marketplace add kepano/obsidian-skills
/plugin install obsidian@obsidian-skills
```

このプロジェクトの`CLAUDE.md`は共通規約への入口のみ。スキルの自動発見やプロジェクト規約の読込みは環境ごとに確認し、「入れたはず」で作業を始めない。導入が使えない環境でもMarkdownの読み書きとPython検査は可能。できないアプリ操作は未実施と報告する。

## Obsidianと表示用プラグイン

先に[共同編集の初回セットアップ](18_GitHub共同編集.md)を行い、ルートを保管庫として開く。共有初期設定は既存の個人設定を上書きしない。

表示拡張は[Extended Graph](https://github.com/ElsaTam/obsidian-extended-graph)を各自で導入する。今回の共有設定を作った環境は**2.7.6**。互換性を揃えるときはこの版で確認し、更新版を使う場合は表示を確認する。導入はObsidianのコミュニティプラグイン、または上流のリリース手順に従う。プラグイン本体はGitで配らない。

初回セットアップでコピー済みの`plugins/extended-graph/data.json`がある場合は保持する。プラグインの初回有効化後に、最大の丸T00、立場色、種類別形、本筋・詳細の2ブックマークを確認する。標準グラフの自然配置を使い、固定配置に戻さない。プラグインなしでも正本・Canvas・ローカル閲覧HTMLで検討できる。

`setup_extended_graph.py`は設定を変更するため、導入済みの各自の環境で常用しない。通常更新は`reasoning_graph.py`だけを使う。

## CLIの準備と安全な対象指定

[公式CLI案内](https://obsidian.md/help/cli)を確認し、アプリ設定の「一般」からCLIを有効化する。公式案内は1.12.7以上のインストーラーと登録手順を示している。実際のコマンドはその端末の`obsidian help`で確認する。最初の実行がアプリを起動する場合があるため、対象の保管庫を先に開く。

```powershell
obsidian help
obsidian vault="模擬裁判_検察官準備_20261020" read path="検討/ノート/T00.md"
obsidian vault="模擬裁判_検察官準備_20261020" reload
```

複数保管庫を使うときは`vault=`を必ず指定し、最前面の別保管庫への誤操作を避ける。上は読取とreloadだけで、内容変更は行わない。GUIの自動操作は使わない。CLIが使えない場合はファイル更新と検査を進め、アプリ再読込・表示確認が未実施と記録する。

Windowsの「検討を更新.cmd」は仮想環境があればそれを優先する。起動中アプリのreloadは対象保管庫を明示し、CLIが見つからなければファイル更新だけ行う。macOS/LinuxではPythonで更新し、利用可能なCLIを別途実行する。

## 最初の動作確認

1. AIが共通規約を読み、対象IDと出典ページを示せることを確認する。
2. `python 作成用/verify_repository.py`を実行する。原資料・正本・派生の不一致は直してから編集を続ける。
3. `python 作成用/reasoning_graph.py --gate T00`の保留理由を読む。インストール成功のために人のreviewや採否を変更しない。
4. Obsidianの本筋・詳細・正本へのリンクと、ブラウザの接続閲覧画面を確認する。新規端末の表示確認は担当者が記録する。

導入元の案内はツールの外部参考であり、事件教材や証拠ではない。
