## 双方の検討を読む

### 今回のブレインストーミングをたどる

子ワーカー3担当（検察・弁護・確認質問）が、既存の命題と接続をたどり、正本の「2026-10-21 グラフを使ったブレインストーミング」へ検討を追記しています。**AI案・人のレビュー前**です。新しい供述や証拠を得たという意味ではありません。

1. **眼鏡の枝**：[[検討/ノート/R02|R02 在場の推認]] → [[検討/ノート/D03|D03 所有と行為の区別]] → [[検討/ノート/Q01|Q01 清掃の確認]]・[[検討/ノート/Q02|Q02 紛失の記憶]]。「清掃が検察に有利でも、着用・刺突まで何が残るか」を双方から読む。
2. **自転車・映像の枝**：[[検討/ノート/R03|R03 自転車]]・[[検討/ノート/R04|R04 映像]] → [[検討/ノート/D04|D04 共用の問題]]・[[検討/ノート/D05|D05 同一性の問題]] → [[検討/ノート/Q03|Q03 利用者の確認]]。二つの枝が同じ未確認の本人特定に依存していないかを比べる。
3. **全体へ戻る**：[[検討/ノート/R05|R05 動機の補助]] → [[検討/ノート/T01|T01 犯人性]] ↔ [[検討/ノート/D09|D09 弁護の全体評価]]。各枝が独自に何を追加し、結合してもどこが未特定かを確認する。

この読み順の矢印は閲覧順であり、支持関係の追加ではありません。支持・反論・確認の関係は正本属性と各カードの接続表で読みます。今回は既存関係の理由と限界を掘り下げ、採否・人のレビュー・配置は維持します。

裁判官視点では [[docs/15_裁判官視点と判決の分岐|判決の分岐と尋問の条件]] から読みます。眼鏡と刺突の結び付きが核心、Bの観察と紛失の記憶が尋問の最優先です。「一つの回答で有罪・無罪が決まる条件」とせず、最終の立証条件と各質問で支える段階を分けました。法令・判例は [[docs/外部参考/01_刑事事実認定の公式資料|外部参考]] です。正本14件に「裁判官視点の条件」を追記しましたが、実際の裁判官の判断や人のレビューではありません。

2026-10-21、検察・弁護の検討を既存カードに追記しました。まず [[docs/13_双方の立証構造と評価|双方の立証構造と評価]] → [[検討/ノート/T01|T01 犯人性]]・[[検討/ノート/D09|D09 弁護の全体評価]] → [[検討/ノート/R02|R02 眼鏡からの在場推認]]・[[検討/ノート/D03|D03 所有と行為の区別]] → [[検討/ノート/R01|R01 清掃後の到達]]・[[検討/ノート/D01|D01 観察の限界]] の順に読むと、双方の応答と残る疑問を比較できます。

各正本の「2026-10-21 双方検討」と「反論への応答」は **AIの案・人のレビュー前**。人のコメント欄・判断属性は保持しています。[[docs/14_尋問の優先順位と回答分岐|優先質問17件と回答別の更新]] では想定と実際の回答を分けました。清掃等は法廷未確認で、原稿化の制約は残ります。グラフの派生ノートからは末尾の正本リンクで追記を読めます。

## 開く

左のブックマークから「模擬裁判・構造グラフ」→「01 論証の本筋」を開きます。証拠・事実命題・推認・要証事実・反論の34点を直接結びます。確認・尋問準備まで見るときは「02 詳細・準備と確認を含む」（43点）へ。CLIでは `obsidian command id=graph:open`。点をクリックすると表示用ノートが開き、末尾から正本へ戻れます。

| 見え方 | 意味 |
|---|---|
| 最大の丸 T00 | 「被告人は有罪である」＝検察側の最終立証目標・未認定 |
| 次に大きな T01・D09 | 主争点の犯人性と、それに対する弁護の総合反論を表示上強調 |
| 青／赤／灰 | 検察／弁護／双方共通。自然配置なので色の異なる点が隣接することもある |
| 四角／丸／ひし形 | 証拠／事実命題／推認 |
| 六角形／三角形／五角形／八角形 | 要証事実／反論／確認課題／準備資料・供述候補 |
| 直接つながる矢印 | 起点→対象。支持・反論・確認・準備・将来候補の区別はカード内の接続表で確認 |
| ⚠と利用状態 | 留保・未獲得・未確認の前提あり。詳細はノートに記載 |

点の大きさは表示上の重要度です。証拠力・独立証拠数・有罪確率を表しません。Fの「事実命題」も認定済みとは限りません。E07・E09は準備資料、W01・W02は未獲得の供述候補のままです。

確認課題Q01〜Q05、準備資料E07・E09、供述候補W01・W02は通常表示から省いています。各カードの「このカードに入る接続」から開けます。留保・未確認の前提に依存する命題の⚠表示や、原稿化の制約は残ります。

## 検討と編集

1. T01から推認を一つ選び、出発点の証拠と原資料の号証・ページを確認します。
2. 対応する弁護の反論と確認課題も開きます。例：R01 → D01・Q01、前提のF03・E10。
3. `ノート/` の正本に前提、別の説明、残る疑問、人のコメントを記録します。
4. 人が判断した場合だけ `review`・`reviewer`・`reviewed_on` を記録します。人の「採用」と裁判所の採用は別です。
5. 「検討を更新.cmd」を実行します。グラフと一覧を同期し、CLIが有効ならグラフ拡張も再読込します。

[[検討/論証一覧.base|論証一覧]]は、全件・検察・弁護・共通資料・準備確認の5ビュー。行を編集すると正本の属性が変わるので、証拠状態と人のレビューを混同しないでください。

## 検査と原稿化

```powershell
python 作成用/reasoning_graph.py --check
python 作成用/reasoning_graph.py --gate T00
```

原稿化チェックの保留・終了コード2は想定された結果です。検査が通っても法的な証明の十分性を保証しません。甲3・乙2を現在の認定根拠にするには実際の法廷供述等を確認し、新しい記録へ分離してください。原稿化は段落の主張と根拠ノートを人が確認してから行います。
